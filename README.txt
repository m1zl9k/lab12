Контрольные вопросы для защиты работы
> 1. **Порядок байт:** Зачем в структуре данных sockaddr\_in мы принудительно переворачивали байты порта (8080 $\rightarrow$ 0x901F) и IP-адреса? Какая фундаментальная разница существует между архитектурными концепциями порядка байт процессоров x86-64 (*Little-Endian*) и сетевых протоколов интернета (*Big-Endian*)?  
> 2. **Анализ регистров:** Если бы мы отлаживали программу в отладчике gdb, в каком физическом регистре процессора и в каком виде (положительное или отрицательное число) мы бы увидели код ошибки системного вызова connect, если бы сервер netcat не был предварительно запущен? Как ядро Linux сигнализирует коду Ring 3 об ошибках вызовов через регистры?  
> 3. **Сравнение абстракций:** Опишите на основе выполненных работ цепочку трансформации: во что превращается метод высокого уровня socket.send() в Python на уровне машинных регистров процессора и системных вызовов ядра ОС?


1. Зачем переворачивали: x86-64 хранит числа в Little-Endian (младший байт первый), а сетевые протоколы TCP/IP - в Big-Endian (старший байт первый). Порт 8080 = 0x1F90. В Big-Endian это байты 1F 90. NASM на x86 запишет dw 0x901F в память как 1F 90 - то есть «перевёрнутое» число даёт правильный сетевой порядок. Аналогично IP 127.0.0.1 = 0x7F000001 -> пишем dd 0x0100007F, в памяти получаем 7F 00 00 01. Разница Little-Endian (x86-64): младший байт по младшему адресу. Удобно для арифметики. Big-Endian (сеть): старший байт первый. Единый стандарт для всех сетевых протоколов (RFC 1700), чтобы разные процессоры понимали друг друга.

2. Регистр: RAX. Вид: отрицательное число в диапазоне [-4095, -1]. При ECONNREFUSED (111) RAX = -111 (0xFFFFFFFFFFFFFF91). Как ядро сигнализирует: после syscall результат в RAX. Если RAX принадлежит [-4095, -1] - это код ошибки (модуль = номер errno). Если RAX больше или равен 0 - успех. glibc проверяет это и записывает модуль в errno.

3.Метод sock.send(b"Hello") в Python превращается в один системный вызов ядра.
Цепочка: Python: sock.send(b"Hello") → CPython вызывает send(fd, buf, len, 0) из glibc. 
glibc: заполняет регистры и выполняет syscall:
RAX = 44 (sys_sendto) или 1 (sys_write)
RDI = дескриптор сокета
RSI = указатель на буфер в ОЗУ процесса
RDX = длина буфера
R10 = 0 (флаги)
Ядро (Ring 0): копирует байты в TX-буфер сокета -> TCP-стек добавляет TCP-заголовок -> IP-стек добавляет IP-заголовок -> драйвер NIC формирует Ethernet-кадр -> сетевая карта отправляет сигнал.
Возврат: RAX = количество отправленных байт (или отрицательное число при ошибке).
Вывод: send() - обёртка над одним syscall. Вся работа с сетью (упаковка пакетов, работа с картой) происходит в Ring 0.
